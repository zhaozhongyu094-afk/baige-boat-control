# 百舸船控通信协议 v1

本页的二进制协议适用于安卓遥控器 v1.2 起的船端 PWM 模式和本仓库的 BoatPWM 固件。v1.6 另支持原版 51 固件，见文末。

## 操作与四路输出

| 摇杆 | 左桨指令 | 右桨指令 |
|---|---|---|
| 直前 / 直后 | 同向、随幅度变化 | 同向、随幅度变化 |
| 向右前方推 | 较快正转 | 较慢、停转或反转，取决于横向分量 |
| 水平向右 / 向左 | 正转 / 反转 | 反转 / 正转 |
| 松手、立即停车 | 0 | 0 |

L298 的两路使能沿用原运行时有效状态。定时器 0 直接对原方向脚做软件 PWM，无需另接使能脚。P20/P21 对应右桨 IN1/IN2，P22/P23 对应左桨 IN3/IN4。正向输出的右侧电平为 10、左侧为 01，沿用旧程序的电机极性。每个 PWM 周期的关断部分两输入同为低电平，采用 L298 制动状态。

软件 PWM 每步 230 个机器周期，每周期 32 步。在 11.0592 MHz、12T 下，频率约 125.2 Hz，每侧正反各 32 个非零占空比，另有零档。32 档是电气输出分辨率，低档带桨能否起转取决于电机和负载。

## 串口协议 v1

JDY-31 透明传输原始二进制字节。定时器 1 产生 9600 波特率。手机每 50 ms 发送一帧，松手、取消触摸或按停车键时立即补发中位帧。旧版五个 ASCII 数字命令已由下表中的控制帧取代，两端需配套使用。

| 方向 | 帧字节，均为十六进制格式 |
|---|---|
| 手机 → 船，7 字节 | `FF 01 SEQ X Y CRC_H CRC_L` |
| 船 → 手机，6 字节 | `FE 01 SEQ ARM CRC_H CRC_L` |

- `01` 是协议版本。序号 `SEQ` 从 0 到 127 循环，回执原样带回所确认的序号。
- X 向右为正，Y 向前为正。线上数值为实际指令加 100，范围 0～200，中心是十进制 100，即 `64`。界面以 8% 的径向死区过滤中心抖动，余下行程线性映射至满幅。
- 船端计算左桨 `Y + X`、右桨 `Y - X`，此处 X、Y 已减去偏移。若绝对值最大者超过 100，两侧按同一比例缩小，再四舍五入至 32 档。
- CRC 采用 CRC-8，多项式 `0x07`，初值 0，不反射，无最终异或。范围从版本字节至最后一个数据字节。结果拆成高、低两个四位数，各占一个字节，即 `0x00～0x0F`。帧头不会出现在合法数据中，接收机遇到新帧头即可重新对齐。
- `ARM=1` 表示船端已接受控制，`ARM=0` 表示必须先发中位。上电和控制超时后，只接受中位来重新启用驱动。已启用时，非中位帧只接受相对上次序号向前 1～63 的帧，过期或重复的运动指令不续期。中位停车可随时接受。
- 自最后一帧有效控制起，约 0.31 s 后船端自动清零输出并解除驱动许可。手机超过 350 ms 未收到新鲜回执，也将摇杆回中、清除当前触摸并只发中位。重新就绪后需重新触碰摇杆。手机切到后台时关闭 SPP，并尝试先发中位，链路已断时由船端超时停车。
- 回执确认的是固件接受控制指令，没有测速反馈。

**可直接输入串口工具的十六进制例子**

| 先后顺序 | 控制帧 | 预期结果 |
|---|---|---|
| ① | `FF 01 00 64 64 08 0C` | 中位，船回 `FE 01 00 01 06 0C` |
| ② | `FF 01 01 64 96 03 07` | 直前，两侧 50% |
| ③ | `FF 01 02 96 96 0B 04` | 向右前方转，左桨 100%、右桨 0 |
| ④ | `FF 01 03 64 64 03 01` | 停车 |

连续验证时，相邻控制帧须在超时前送达。手动逐行输入时可用定时发送脚本按 50 ms 更新序号和 CRC。

## v1.6 旧版兼容模式

在连接前打开设置，在「控制协议」中选择「旧版兼容模式」。船端沿用资料库原版 51 蓝牙船程序。手机发单个 ASCII 数字，船端逐条回复 `OK`。数字 1、2、3、4、5 分别为前进、后退、左转、右转、停车。旧船转弯时只驱动外侧桨，方向模式下推杆幅度不改变速度。App 先发 5，收到确认后才允许行驶。新版二进制模式在未握手时始终使用序号 0 的固定中位探测帧。

「蓝牙点动调速」默认关闭。v1.6.1 可在旧版兼容设置中选 4、8 或 12 Hz，首次启用默认 8 Hz。按摇杆幅度分 25%、50%、75%、100% 四档。8 Hz 的周期为 125 ms，25% 档每周期目标行驶约 31 ms、停车约 94 ms。100% 档持续行驶。表盘显示指令占比。松手会立即请求停桨，重新推杆前须收齐上次指令的回执。持续点动时如调度停顿超过半个周期（上限 95 ms）或运动期间等待回执超过 125 ms，App 尝试发 5 并结束会话。原版固件没有船端失联超时，链路中断后可能继续执行上一条命令。

在仓库根目录运行 `node --test android/tests/legacy.test.cjs` 可复现串口模型测试。测试检查每档的累计通电时间及脉冲次数，也检查松手后在途回执不能重新启动电机。单向延迟在 10–40 ms 间变化时，8 Hz 四档在 8 秒窗口内的模型通电占比分别为 26.7%、51.4%、75.2%、99.4%。单向 20–90 ms 的测试序列触发回执超时。这些数据来自软件模型，电机转速和船体顿挫需要实船测量。
